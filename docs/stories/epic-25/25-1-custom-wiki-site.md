# Story 25-1: Custom Wiki Site

**Epic:** 25 -- Documentation & Wiki Site
**Priority:** P1
**Status:** Planned
**Estimated Effort:** 3-5 days

## Summary

Build a custom documentation/wiki site using Astro Starlight, deployed to Cloudflare Workers at wiki.tamma.dev and wiki.its-done.dev. The site sources its content from the repository's `wiki/` and `docs/stories/` directories, features collapsible sidebar navigation grouped by epic, full-text search via Pagefind, dark/light theme support, and auto-deploys via GitHub Actions when content changes.

- [ ] Home page shows project overview (derived from wiki/Home.md)

- [ ] Architecture page renders diagrams/code blocks correctly
- [ ] GitHub Actions workflow auto-deploys on changes to `wiki/**`, `docs/stories/**`, or `apps/wiki-site/**`
- [ ] Build completes in under 60 seconds

## Technical Design

### 1. Framework Choice: Astro Starlight

**Why Starlight:**
- Purpose-built for documentation sites (not a generic SSG)
- Built-in Pagefind integration for full-text search -- no backend needed, WASM-compiled, searches pre-built static indexes
- Zero client-side JavaScript for content pages (only nav toggle, dark mode switch, and search ship JS)
- Collapsible sidebar navigation with autogenerated groups from directory structure
- Dark/light mode built-in with CSS custom property theming
- Markdown, MDX, and Markdoc support
- Accessibility-first design (WCAG 2.1 AA)
- First-class Cloudflare support -- Astro joined Cloudflare in Feb 2026; Astro 6 has native workerd dev server support
- Used by Cloudflare, Google, Microsoft, OpenAI for their documentation

**Alternatives considered:**
- **VitePress** -- Vue-only, less documentation-focused, no built-in search as polished as Pagefind
- **Docusaurus** -- React-based, heavier bundle, slower builds, no native CF Workers support
- **MkDocs Material** -- Python-based, doesn't fit the TypeScript monorepo
- **Custom from scratch** -- Too much effort for what Starlight provides out of the box

### 2. Hosting: Cloudflare Workers

**Why Workers over Pages:**
- The `@astrojs/cloudflare` adapter targets Workers (not Pages) as of 2025
- Astro 6 beta includes native workerd runtime support for `astro dev`
- Workers support custom domains natively -- both wiki.tamma.dev and wiki.its-done.dev can point to the same project
- Workers has a 25MB compressed size limit (more than enough for static docs)
- Edge-cached globally via Cloudflare CDN

**Multi-domain setup:**
- Deploy a single Workers project
- Add both `wiki.tamma.dev` and `wiki.its-done.dev` as custom domains in Cloudflare Workers settings
- Both domains share the same zone (already on Cloudflare per existing deployment)

### 3. Content Sourcing Strategy

The site sources content from two locations in the repository. A pre-build Node.js script (`scripts/sync-content.ts`) copies and transforms markdown files into Starlight's expected `src/content/docs/` structure.

#### Source mapping:

```
REPO SOURCE                          -> STARLIGHT CONTENT PATH                -> URL PATH
wiki/Home.md                         -> src/content/docs/index.mdx           -> /
wiki/Roadmap.md                      -> src/content/docs/roadmap.md          -> /roadmap/
wiki/Architecture.md                 -> src/content/docs/architecture.md     -> /architecture/
wiki/Epics.md                        -> src/content/docs/epics/index.md      -> /epics/
wiki/Stories.md                      -> src/content/docs/stories/index.md    -> /stories/
wiki/Contributing.md                 -> src/content/docs/contributing.md     -> /contributing/
wiki/Epics/Epic-1-Foundation.md      -> src/content/docs/epics/1-foundation.md -> /epics/1-foundation/
wiki/Epics/Epic-2-Autonomous-Loop.md -> src/content/docs/epics/2-autonomous-loop.md -> /epics/2-autonomous-loop/
...                                  -> ...                                  -> ...
docs/stories/epic-1/README.md        -> src/content/docs/stories/epic-1/index.md -> /stories/epic-1/
docs/stories/epic-1/story-1-0/*.md   -> src/content/docs/stories/epic-1/1-0-*.md -> /stories/epic-1/1-0-*/
...                                  -> ...                                  -> ...
```

#### Content transformation (sync-content.ts):

The script performs the following transformations:
1. **Add Starlight frontmatter** -- Inject `title`, `description`, and `sidebar` metadata at the top of each file
2. **Transform wiki links** -- Convert `[Text](Epics/Epic-1-Foundation)` to `[Text](/epics/1-foundation/)`
3. **Transform GitHub links** -- Convert `https://github.com/meywd/tamma/tree/main/docs/stories/epic-1` to `/stories/epic-1/`
4. **Preserve code blocks** -- Do not transform content inside fenced code blocks
5. **Handle frontmatter conflicts** -- If a file already has frontmatter, merge rather than overwrite

### 4. Sidebar Configuration

The sidebar uses a mix of manual top-level links and autogenerated epic groups:

```typescript
// astro.config.mjs sidebar configuration
sidebar: [
  { label: 'Home', link: '/' },
  { label: 'Roadmap', link: '/roadmap/' },
  { label: 'Architecture', link: '/architecture/' },
  {
    label: 'Epics',
    collapsed: true,
    autogenerate: { directory: 'epics' },
  },
  {
    label: 'Stories',
    collapsed: true,
    items: [
      { label: 'Overview', link: '/stories/' },
      { label: 'Epic 1: Foundation', collapsed: true, autogenerate: { directory: 'stories/epic-1' } },
      { label: 'Epic 1.5: Infrastructure', collapsed: true, autogenerate: { directory: 'stories/epic-1.5' } },
      { label: 'Epic 2: Autonomous Loop', collapsed: true, autogenerate: { directory: 'stories/epic-2' } },
      // ... all epics
    ],
  },
  { label: 'Contributing', link: '/contributing/' },
]
```

Since there are 24+ epics, the sidebar configuration will be generated programmatically in `astro.config.mjs` by reading the directory listing.

### 5. Custom Theming

Starlight supports CSS custom property overrides for branding. The Tamma wiki uses the existing purple brand color from the marketing site.

```css
/* src/styles/custom.css */
:root {
  --sl-color-accent-low: #2d1b69;      /* Dark purple */
  --sl-color-accent: #7c3aed;          /* Tamma purple */
  --sl-color-accent-high: #c4b5fd;     /* Light purple */
  --sl-font-system: 'Inter', -apple-system, BlinkMacSystemFont, sans-serif;
}
```

Logo variants for dark and light mode will be placed in `src/assets/`.

### 6. Roadmap Page

The Roadmap page at `/roadmap/` will include a visual timeline. This can be done with:
- **Option A:** A custom Astro component using CSS grid/flexbox to render the phase timeline from wiki/Roadmap.md's ASCII art
- **Option B:** A Mermaid diagram rendered at build time via `astro-mermaid` or `remark-mermaid`
- **Recommended:** Option A -- a simple custom `<Timeline>` component in `src/components/Timeline.astro` that reads structured data and renders a visual gantt-style chart

### 7. GitHub Actions Deployment

```yaml
# .github/workflows/wiki-deploy.yml
name: Deploy Wiki Site
on:
  push:
    paths:
      - 'wiki/**'
      - 'docs/stories/**'
      - 'apps/wiki-site/**'
    branches:
      - main
  workflow_dispatch: {}

jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - uses: actions/checkout@v4

      - uses: pnpm/action-setup@v4
        with:
          version: 9

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - name: Install dependencies
        run: pnpm install --filter @tamma/wiki-site...

      - name: Sync content from wiki/ and docs/stories/
        run: pnpm --filter @tamma/wiki-site sync-content

      - name: Build
        run: pnpm --filter @tamma/wiki-site build

      - name: Deploy to Cloudflare Workers
        uses: cloudflare/wrangler-action@v3
        with:
          apiToken: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          workingDirectory: apps/wiki-site
          command: deploy
```

### Content Volume
- wiki/ directory: 33 markdown files
- docs/stories/ directory: ~464 markdown files
- Total: ~497 pages to render
- Estimated build time: 30-45 seconds (Astro is fast for static sites)

### Pagefind Search
- Pagefind is built into Starlight by default
- It indexes all static HTML at build time
- Search runs entirely client-side using a WASM binary
- No backend, no API calls, no external service needed
- Supports fuzzy matching and result highlighting

### Performance Considerations
- All content pages are pre-rendered as static HTML (zero client JS)
- Pagefind search index is lazy-loaded only when user clicks search
- Images should be optimized at build time via Astro's built-in image optimization
- Cloudflare Workers serves from the nearest edge location globally
- Cache-Control headers should be set for static assets (long TTL) and HTML (short TTL with revalidation)

### Multiple Domains
- Cloudflare Workers supports multiple custom domains per project
- Both wiki.tamma.dev and wiki.its-done.dev will be configured as custom domains
- No code changes needed to support multiple domains -- it's purely a Cloudflare routing configuration
