# Completeness Audit — `LlmCallWorkflow` (LLM Call Sub-Workflow)

**Date:** 2026-06-22 · **Audited file:** `apps/tamma-elsa/src/Tamma.ElsaServer/Workflows/LlmCallWorkflow.cs` (DefinitionId `llm-call`) · **Read-only code audit** · **Maturity verdict: PARTIAL**

---

## Purpose & owner

`LlmCallWorkflow` is the **universal building block for every AI operation in Tamma** — the sub-workflow that ~16 parent workflows (`SingleIssueCycle`, `Tdd*`, `CodeReview`, `BlockerDiagnosis`, `PlanGeneration`, `Mentorship`, …) dispatch via `DispatchWorkflow` whenever they need an LLM call. It owns provider-chain selection, circuit-breaker/budget gating, retry with backoff, 6-level prompt resolution, the agentic tool loop, and structured output (`llmResponse`/`providerUsed`/`costUsd`/`tokensUsed`/`success`/`workflowOutput`).

**Owning epic/story:** the resilience scaffold is legacy Epic 9/11/12 + 27 (prompt/convention/tool-loop). The **target architecture** is **Epic 32 — Agents** (the 2026-06-20 pivot), specifically **Story 32-5** (call-LLM endpoint + managed execution, the pivot lynchpin / sequence step F), with hard prerequisites 34-11 (provider cost price-book), 32-15/16/17/18 (personas/enablement/custom-prompts/registry gate), 32-4 (SaaS provider gate), 32-3 (BYOK credential resolution), and Epic 38 (non-LLM step mediation).

---

## Maturity: **PARTIAL**

This is **not** a thin happy-path stub like the `PullRequest` workflow. The resilience machinery is genuinely built out and robust. But the workflow is constructed on the **pre-pivot architecture** that the 2026-06-20 design of record (§0 rule 1, §1, §2) and Story 32-5 explicitly supersede: the Elsa engine calls Anthropic/OpenAI **directly, holding the provider key in-engine**. Per the design that is the single worst "rule 1" violation in the codebase. The mediation endpoint (`POST /api/v1/llm/call`), the managed-execution composition, server-side metering, and the `AGENT.RUN.*` audit trail do not exist. So: core present and correct on resilience; the execution model and the audit/metering/gating contract are missing → **partial**, not complete.

## Current capabilities (what it actually does today)

Flow: `InitInputs → ResolveConventions → MergeConventions → ResolvePrompt → SetupBudget → ResolveAgentConfig → ResolveChain → CheckConcurrency →[OK] ForEachProviderChain → FailureCheck →[T] SetOutputs / [F] BuildFailureOutput → SetOutputs`; `CheckConcurrency →[AtLimit] ConcurrencyDelay → (loop)`.

- **Dual input contract.** Typed inputs (`agentRole`/`action`/`variables`/`taskPrompt`/`tenantId`/`enableTools`/`toolLoopConfig`/`systemPromptOverride`) **and** a legacy `InputJson` (`LlmCallWorkflowInput`) fallback, plus dict-style (`role`/`content`) inputs from BlockerDiagnosis-style callers.
- **Convention resolution (27-13).** `ResolveConventionsActivity` (store → legacy `.tamma/config.json` passthrough), merged into the `{{conventions}}` template variable. `MergeConventions` fails loud (`TammaError LLM.CONVENTIONS.MERGE.MALFORMED_VARIABLES_JSON`) on malformed upstream JSON — no silent variable stripping.
- **Prompt resolution (27-6/27-18), fail-loud.** `ResolvePromptFromRegistryActivity` POSTs `/api/prompts/{role}/{action}/render` with `X-Tenant-Id` (tenant→system→error); a registry miss/5xx/4xx throws a typed `TammaError` (`REGISTRY_UNAVAILABLE` retryable / `NO_ROW` non-retryable) — **never** a silent plain-prompt fallback. Empty-action legacy passthrough retained.
- **Agent config resolution (9-11).** `ResolveAgentConfigActivity` calls `TammaApiClient.ResolveAgentAsync` for provider chain + system prompt (already a correct engine→API callback).
- **Provider chain.** Priority: caller input > DB agent config > default `[anthropic, openai, openrouter]`, filtered through `ProviderAllowlist` — **fails loud** if the allowlist rejects all (no silent fallback).
- **Concurrency gate.** `CheckLlmConcurrencyActivity` (counts Elsa `Running` `llm-call` instances) with an `AtLimit → ConcurrencyDelay → re-check` wait loop.
- **Per-provider resilience (`ForEach<provider>`).** `SkipIfSucceeded` → circuit-breaker check (fail-**closed** on parse error) → budget check (fail-**closed**) → resolve tools → `BuildRetryLoop`.
- **Retry loop.** `While(!success && attempt<=maxRetries)`; `RetryCheck` retries on `HttpStatusCode ∈ {429,502,503,504,0}`, else exhausts; `SuccessCheck` builds the success output with token/cost/diagnostics.
- **The actual LLM call (`CallLlmInlineActivity`, ~1592 LOC).** Single-turn **and** a full agentic tool loop: prompt sanitization (`IContentSanitizer`), multi-turn Anthropic Messages / OpenAI-compatible call, tool-call validation (`IToolCallValidator`), sequential + parallel tool execution, tool-output sanitization + secret redaction, context compaction (`ContextCompactor`), token accounting, exponential backoff, BYOK→platform credential resolution (32-3, `IProviderCredentialResolver`, fail-closed `PROVIDER_CREDENTIAL_UNAVAILABLE`), `credentialSource` on the diagnostic, an (inert) `ToolLoopEventEmitter` streaming seam.
- **Structured outputs.** `SetOutputs` emits `success`, `workflowOutput`, `llmResponse`, `providerUsed`, `costUsd`, `tokensUsed`, `toolLoopTokens/Turns/Exhausted`. Failure path builds an explicit `BuildFailureOutput` (`success:false`, "All providers in the chain failed", diagnostics) → no false-success.

## Intended full scope (with citations)

The design of record (`docs/superpowers/specs/2026-06-20-epic-32-revised-agent-architecture.md` §0 rules 1–7, §1) and the deep-dive (`docs/superpowers/specs/2026-06-20-managed-llm-execution-deep-dive.md` §1–§5) define the complete target. **Story 32-5** (`docs/stories/epic-32/story-32-5/32-5-managed-agent-execution-layer.md`) is the implementing spec.

A complete LLM-call flow must:

1. **Never call a provider from the engine** (design §0.1, §1.1). The step calls an internal `POST /api/v1/llm/call` in `Tamma.Api`; the engine holds **no** provider key and opens **no** provider socket. Co-hosting is explicitly **not** compliance (§1.1) — it breaks the moment the engine runs as Cranl per-tenant compute.
2. **Mediate through a managed-execution composition** (design §0.2, 32-5 AC3): `gate (32-4) → budget (server-side, fail-closed) → resolve agent + per-tenant enablement (32-2/32-16/32-18) → resolve credential BYOK→platform (32-3 cabinet) → render prompt (Epic 27 persona / 32-17 custom, tenant→system→**error**) → provider call via the extracted `IInlineToolLoopRunner` with a request-scoped key → meter (`IProviderPricingService.Compute` 34-11 cost basis + 34-5 markup-when-platform + 32-9 usage event) → return`.
3. **Honour the load-bearing status contract** (32-5 AC6/AC7): expected provider failures return **HTTP 200 + `success:false` + preserved `httpStatusCode`** (so the workflow's `RetryCheck`/circuit-breaker keep working); gate denial → 400 `SAAS_PROVIDER_NOT_ALLOWED`; entitlement → 403; engine bearer → 401; a raw 5xx must **never** leak (it would be nulled by `TammaApiClient.PostAsync`).
4. **Keep provider-chain + retry at the workflow boundary, byte-for-byte** (32-5 AC6, deep-dive §2): `BuildRetryLoop`/`ForEach`/`RetryCheck`/`SkipIfSucceeded` unchanged; `CallLlmInlineActivity` collapses to a ~80-line thin client that maps to `LlmCallRequest`, calls `TammaApiClient.CallLlmAsync`, and writes the **same** `LastDiagnostic`/`LastResponse`/`ToolLoop*` variables.
5. **Emit a DCB audit trail from the API** (32-5 AC8, design §0.2f): one `AGENT.RUN.STARTED` + exactly one terminal `AGENT.RUN.SUCCESS|FAILED`, tagged `{agentId, version, provider, model, role, correlationId, credentialSource, tenantId(+failureCode)}`, plus `AGENT.CREDENTIAL_RESOLVED.*` / `AGENT.PROVIDER.GATED`, written via the tenant `IEventRepository`. `AgentRunResult` is the producer record consumed by 32-6 (action trail) / 32-8 (outcome) / 32-9 (usage).
6. **Personas/custom agents + per-tenant enablement** (design §0.4–6, 32-15/16/17/18): resolution applies the `TenantAgentEnablement` gate; personas use Epic 27 prompts, custom agents use their own prompts.
7. **Managed-execution depth** (deep-dive §3–§5, follow-ons): buffered + SSE response modes with a live `IToolLoopEventSink`; MCP/plugin tool sourcing (C# net-new); prompt cache + optional gated response cache; **interactive question-back** (`request_input` tool + `IQuestionRouter` + `QuestionRoutingPolicy` + durable `WaitForAgentQuestionActivity`) — "the single most novel piece."
8. **14-step autonomous loop fit** (`docs/architecture.md`): every AI step in the loop must produce a 100%-audit-trail event for time-travel debugging and metered cost — which the managed run provides and the current direct-call path does not.

## Ordered build-out spec (to reach complete, robust)

The workflow **graph stays byte-for-byte unchanged**; the work is behind the `CallLlmInlineActivity` boundary plus new `Tamma.Api` surface. Sequence respects the migration-snapshot rule (do prerequisites first) and the lynchpin ordering of 32-5.

1. **Land prerequisites** (sequence A–E of the re-plan): 34-11 provider cost price-book (behind `IProviderPricingService.Compute`); 32-15 persona reframe + Epic-27 wiring; 32-16 `TenantAgentEnablement`; 32-17 custom-agent prompts; 32-18 registry enablement gate + Epic-27 prompt-source; 32-4 (rewrite) `ISaaSProviderGate.InspectAsync` as an endpoint stage. (These gate 32-5.)
2. **Extract the tool loop verbatim** into `IInlineToolLoopRunner` / `InlineToolLoopRunner` under `Tamma.Activities/LlmCall/` — pure move of `CallLlmInlineActivity.AgenticToolLoop` + multi-turn builders/parsers + `LoadProviderConfig` + sanitize/redact/compaction. Regression net: `CallLlmInlineActivitySanitizationTests` must pass **unchanged** (if it needs edits, the extraction is wrong). `grep` proves exactly one tool-loop copy.
3. **Build the wire contract.** `LlmCallRequest` (`{tenantId?, agentId?, persona?, role, action?, phase?, prompt, variables, model?, tools?, enableToolLoop, toolLoopConfig?, params{maxTokens,temperature,budgetCapUsd}, correlationId}`) and `LlmCallResponse` (`{success, text, usage{prompt/completion/total/toolLoopTokens/Turns/Exhausted}, credentialSource, providerUsed, modelUsed, cost{providerCostUsd,priceUsd,currency}, toolCalls[], agentId, agentVersion, role, correlationId, durationMs, failureCode?, failureReason?, httpStatusCode?}`) + Usage/Cost/ToolCall DTOs. **Key never in the response/logs/events.**
4. **Build `ManagedAgent.RunAsync`** in `Tamma.Api/Services/Agents/` composing the locked rule-2 sequence: **(1) gate** 32-4 → CLI-in-SaaS `400 SAAS_PROVIDER_NOT_ALLOWED` / entitlement `403`; **(1b) budget** server-side fail-closed → `200 success:false BUDGET_EXCEEDED` (provider never called); **(2) resolve agent + enablement** 32-18/32-16 → `Provider/Model/AgentId/Version/Tools`; **(3) credential** 32-3 cabinet BYOK→platform → null ⇒ `200 success:false PROVIDER_CREDENTIAL_UNAVAILABLE` (`retryable:false, severity:High`); **(4) render prompt** Epic 27 persona / 32-17 custom, tenant→system→**error** (never empty/plain); **(5) emit `AGENT.RUN.STARTED`**; **(6) loop** `IInlineToolLoopRunner` with request-scoped key → `PROVIDER_ERROR` (+preserved `httpStatusCode`) / `LOOP_EXHAUSTED`; **(7) meter** `IProviderPricingService.Compute` cost basis + 34-5 markup(platform)/0(byok) + 32-9 usage event; **(8) emit exactly one terminal `AGENT.RUN.SUCCESS|FAILED`** (tagged `+failureCode` on failure) via tenant `IEventRepository`; **(9) return `AgentRunResult` → `LlmCallResponse`**. Wrap every step so a thrown failure still yields `AgentRunResult{Success=false}` + one terminal `AGENT.RUN.FAILED` — **failures never lose the run record**.
5. **Build the endpoint** `POST /api/v1/llm/call` (`LlmCallEndpoints.cs`), internal/engine-only, `[Authorize]` on `TammaEngineAuthHandler` (Bearer `Tamma:ApiToken`) + `X-Tenant-Id`; bind `LlmCallRequest`, derive `tenantId` from header when body omits it, delegate to `IManagedAgent`. **Mapper enforces the §2.4 status discipline**: 200 success | 200 `success:false`+`httpStatusCode` | 400 | 403 | 401 — **never a raw 5xx**. Add the HTTP-status-fidelity **guardrail test** (deep-dive §7.9).
6. **Add `TammaApiClient.CallLlmAsync(LlmCallRequest, tenantId, ct)`** following the existing `PostAsync<T>` + `AddTenantHeader` + `RecordHealthAsync` pattern.
7. **Gut `CallLlmInlineActivity`** to a ~80-line thin client: map its `Input<>` props → `LlmCallRequest`; `await _api.CallLlmAsync(...)`; map `LlmCallResponse` → the **same** `LastDiagnostic` (`ProviderAttemptDiagnostic{CredentialSource, HttpStatusCode = resp.HttpStatusCode ?? (success?200:0), InputTokens, OutputTokens, Success}`), `LastResponse` (`NormalizedLlmResponse.From(resp)`), `ToolLoopTokens/Turns/Exhausted`. Owns no key/HTTP/loop. **Verify `LlmCallWorkflow.cs` diff is empty.**
8. **Cut over the other callers** (32-5 AC9): gut/delete `CallLlmActivity`; delete the direct keyed LLM fallback in `WriteTests/WriteImplementation/AnalyzeCode/ApplyRefactoring/ApplyReviewFixes/ClaudeAnalysis/AIDiagnosis` — route through `call-LLM`. `grep` over `Tamma.Activities` for `Anthropic:ApiKey` / `/v1/messages` → zero non-`TammaApiClient` hits.
9. **Delete engine credential wiring** (`ElsaServer/Program.cs`): remove `AddEngineProviderCredentialResolution` + `ConfigPlatformProviderCredentialResolver`; move the provider-side deps (`IHttpClientFactory`, `IContentSanitizer`, `IToolExecutorRegistry`, `IToolCallValidator`, `ContextCompactor`, `ToolLoopEventEmitter`, `ParallelToolExecutor`, `IProviderCredentialResolver`) registration into the API process. Engine holds no LLM key (success metric).
10. **Re-home concurrency/budget** (deep-dive §2 open decisions): decide per-tenant API limiter vs Elsa-instance count for `CheckLlmConcurrencyActivity`; budget gate moves to the endpoint (step 4-1b). Document the chosen owner.
11. **Follow-on — interactive question-back** (P1): add the `request_input` tool, `IQuestionRouter`+`QuestionRoutingPolicy` (`(principal,role,action,kind)` tenant→system→error; server re-derives the human-gate from action reversibility so the model can't downgrade), in-stream fast answers (orchestrator-fact / agent-panel via 32-7) and slow human answers via durable `WaitForAgentQuestionActivity` (Elsa bookmark + `POST /api/v1/agents/questions/{correlationId}/answer` → resume → re-call). Events `AGENT.QUESTION.RAISED/.ANSWERED/.ASSUMED`.
12. **Follow-on — streaming run tap** (P2): buffered (engine default) + SSE for humans; turn the inert `IToolLoopEventSink` live; `GET /api/v1/llm/runs/{correlationId}/stream` fed by an in-process bus.
13. **Follow-on — MCP & plugin tool sourcing (C#)** (P2): union built-in ∪ MCP ∪ plugin tools through `IToolExecutorRegistry.GetAllowed`, intersected with the agent's allowed set, through the `ToolHookRegistry` pre/post hooks; per-tenant MCP config + cabinet creds, enablement-gated.
14. **Follow-on — prompt/response cache** (P3): Anthropic `cache_control:ephemeral` stable prefix feeding cache-rate metering; optional response cache keyed `(tenantId, agentVersion, renderedPromptHash, model, toolset)` strictly after gate/budget (still meters/audits; tool-loop runs likely non-cacheable).
15. **Follow-on — C# harness/CLI adapter** (P3, single-user): local harness path exempt from `/llm/call`; in SaaS it stays structurally unreachable behind the 32-4 gate.

**Validation gates:** `grep` over `Tamma.Activities` finds zero direct provider HTTP/`Anthropic:ApiKey`; `ElsaServer/Program.cs` registers no credential resolver; 100% of mediated runs produce one `AGENT.RUN.STARTED` + exactly one terminal `AGENT.RUN.*` + a metered usage record; one tool-loop copy; `LlmCallWorkflow.cs` diff empty; `CallLlmInlineActivitySanitizationTests` unchanged.
